Project 01 | VeriMCP 2025.11 – 2025.12

VeriMCP — MCP 서버가 설명대로 동작하는지 대신 써보고 점수를 매기는 검증 에이전트

  • 대상카카오 × 한국정보과학회 AI 에이전트 경진대회
  • 0.82TrustScore = 근거 0.85 + 합의 0.78
  • 4 AgentsPlanner, Performer, Estimator, Reporter
Situation
  • 카카오 PlayMCP에 등록되는 MCP 서버는 빠르게 늘지만, 설명대로 동작하는지 확인할 방법은 사용자가 직접 써보는 것뿐
  • 툴이 많고 응답이 자연어라 사람이 일일이 검증하기 어려움
Task
  • 서버 설명만으로 시나리오를 만들어 실제 호출하고, 신뢰도를 점수와 리포트로 돌려주는 에이전트 구축
  • 담당 — 시나리오를 반복 호출하는 구조의 병목인 검증 LLM 추론 가속
Action
  • Planner가 시나리오 생성, Performer가 실제 툴 호출, e5-base 코사인 유사도로 기능을 벗어난 시나리오 필터
  • Estimator — AutoRAG 근거 점수 0.5 + GPT, Kanana, Gemini 3모델 합의 0.5 = TrustScore (단일 모델 편향 방지)
  • 검증 LLM에 EAGLE-1 speculative decoding을 적용해 반복 호출 구간의 응답 지연 단축
Result
  • 카카오 × 한국정보과학회 AI 에이전트 경진대회 대상
  • 데모 세션 TrustScore 0.82 (RAG Fact 0.85, Self Consensus 0.78)
  • 리포트가 "카페 검색에 방탈출 카페가 섞임", "미래 날짜 입력" 같은 오류 영역까지 근거와 함께 제시
Architecture
Chrome Extension (PlayMCP DOM 읽기) ↓ FastAPI 백엔드, In-Memory State ↓ Planner — 시나리오 생성 ↓ Performer — 실제 툴 호출, e5-base 유사도 필터 ↓ Estimator — AutoRAG 0.5 + 3-LLM 0.5 ↓ Reporter — TrustScore, 리포트

Project 02 2026App Store 출시

Aingo

하루 10분 퀴즈로 AI 활용 능력을 키우는 앱. 문항은 검증된 '틀'에서 자동 생성하고 사람이 판정하는 콘텐츠 엔진과 역량 평가 체계를 설계.

Project 02 | Aingo 2026 · AI·SW마에스트로 17기 팀 프로젝트 · App Store 출시 2026.09.05 · 현재 v1.1.0

Aingo — 하루 10분 퀴즈로 AI 활용 능력을 키우는 앱, 문항은 '틀'에서 자동 생성하고 사람이 판정

Role AI 활용 역량 정의 및 평가 체계 설계·검증, 문항 생성 엔진 (팀 프로젝트)

  • App StoreiOS 정식 출시
  • 780문항모형 31개에서 자동 생성한 문항
  • 92.3%웹 체험 완주율 (설문 171, 인터뷰 20)
Situation
  • AI를 잘 쓰고 싶은 사람은 많지만 무엇부터 배울지 막막하고, 긴 강의는 이어지지 않음
  • 매일 짧은 퀴즈로 습관화하려면 'AI 활용 능력'을 실제로 재는 문항을 품질 보장하며 계속 공급해야 함
Task
  • LLM에 자유 생성을 맡기면 품질도, 무엇을 재는지도 흔들림 — 측정할 능력을 먼저 정의
  • 검증된 문항의 판단 구조는 고정한 채 변형만 자동화하고, 잘못된 문항이 사용자에게 닿지 않도록 검수 게이트 설계
Action
  • AI 활용 역량을 5영역(위임 판단, 지시/소통, 산출물 검증, 안전/윤리, 적정 의존)으로 정의, 영역별 시드 문항 51개 직접 작성
  • Gierl & Lai의 템플릿 기반 AIG로 시드를 31개 문항모형으로 승격 — 판단 구조는 고정, 작업과 상황만 변형
  • 최신 AI 뉴스 소재 600여 건을 기계 필터와 LLM 판정으로 모형당 최대 10개 라우팅 → 값 변형으로 문항 생성
  • 5영역을 실제로 재는지는 응답 데이터로 CFA → IRT 검증하도록 평가 체계 설계
Result
  • iOS App Store 정식 출시 — 출시 전 인터뷰 20명, 설문 171건, 웹 체험 완주율 92.3%로 수요 확인
  • 문항 780개 자동 생성, 문항모형 31개는 전문가 검토 진행 중
Architecture
시드 문항 51 → 문항모형 31 (판단 구조 고정, 변형 영역) ↓ 소재 라우팅 — 기계 필터 + LLM 판정 (AI 뉴스 600여 건, 모형당 ≤ 10) ↓ 값 변형 → 문항 780 생성 ↓ 자동 게이트 → 사람 검수 → 전문가 검토 ↓ 응답 데이터로 CFA → IRT 검증

Project 03 | Loremaster 운영 대상 — 프로젝트 AINGO (3인 팀)

Loremaster — Slack에서 Jira와 위키를 움직이는 팀 운영 에이전트, 탐지는 AI가 판정은 사람이

  • 615Jira 이슈 관리 (493건 완료)
  • 347위키 자동 정제 커밋, 3개월 무중단
  • 25문서 충돌 탐지, 사람이 판정 후 해소
Situation
  • 3인 팀의 회의록, 결정, PR 설명이 Slack, Notion, git에 흩어지고 같은 사안에 서로 다른 결정이 문서마다 남음
  • 백로그를 정리하고 문서를 맞추는 일이 개발 시간을 계속 잠식
Task
  • 모든 문서를 하나의 지식원으로 정제하고, 충돌 탐지와 백로그 관리를 에이전트에 위임
  • 단, 실행 권한은 사람에게 — 팀이 실제로 쓰는 운영 도구로 정착시키기
Action
  • VPS에 Hermes Agent 배치, 스킬 15개(서버 11, 로컬 2, 플러그인 2)로 역할 분리
  • refine-wiki — 원본 문서를 개념 단위 위키(git, Obsidian)로 정제 및 커밋, graphify로 지식그래프 구성
  • conflict-detection — 문서 간 모순을 CONFLICT 파일로 남기고 Slack에 보고, 해소는 사람이 판정
  • backlog-proposal — 위키 근거를 붙인 이슈 초안 제안, Slack 승인 게이트(Allow / Deny) 통과분만 Jira에 생성
Result
  • 2026년 6월부터 3개월 연속 운영 — 원본 문서 404개를 개념 노드 105개, 관계 138개의 위키로 정제 (자동 커밋 347회)
  • 충돌 25건 탐지 후 팀 판정, Jira 이슈 615건 관리 및 493건 완료 (2026-09-26 기준 Jira, git, Slack 로그 실측)
Architecture
